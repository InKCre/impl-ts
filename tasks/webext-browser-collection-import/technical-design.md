# WebExt 独立 Peer：修订技术方案

> 2026-10-23 精简修订：用户授权落实[技术审计](technical-audit.md)。配置由主人完整读改，本机保存与网络登记分离；登记不阻断 CRUD，后台工作不依赖界面轮询。当前实现说明以 `docs/30-unit-tdd/webext-collection.md` 为准，实际验收结果在实施接续记录。

2026-10-22，用户接受[完整审计](technical-audit.md)并授权推进。本版替换被审计的候选方案；实施与验证继续，不提交或发布，不修改其他会话领域。

## 执行与依赖

WebExt 使用 WXT、Vue、ui-web 和 `@inkcre/core`，拥有自己的连接、Peer 身份、浏览器权限和 UI。不导入 client-web 私有源码、不借它的会话或代理。独立不等于执行能力相同；现场 DOM、选区、书签和历史只能由本浏览器提供，其他能力按已有精确能力或 Source/Job 合同选择执行者，不绑定 Python/Mac 或任意固定应用。

首轮普通保存和浏览器导入直接由扩展形成图，使用已有 PostgREST Block/Relation CRUD 和 Storage 读写，不要求任何网页专用数据库升级。移除候选 `submit_web_material_v1`、`read_web_material_v1`、回执表和协议版本改动，也不以通用事务框架替代。

content script 只读取现场材料，不初始化秘密配置或签发 JWT。后台捕获连接上下文，检查消息 sender、权限和用户规则，保存本机待办并分批执行。UI 显示本机等待、共享保存和需要处理的区别。MV3 监听同步注册，事件/alarm 驱动有限工作，不依赖常驻进程。Firefox 按其实际后台模型适配。

## 材料图与实际来源

`packages/web-collection` 拥有领域 DTO、构图和普通读取实现；它不是数据库 RPC 客户端。HTML/text 是标准 core 语义块的 inline 内容，PDF 是 `core.pdf.v1` 加 Storage 指针；附注是独立 `core.text.v1`。关系是关联权威，不在 metadata 复制 Block ID。

一次保存使用一个材料 metadata 根，记录获取地址、时间、方式、标题、canonical 提示和覆盖缺口，并关联实际语义内容及附注。手动保存不额外创建没有独立用途的来源根。书签/历史本身有原生 ID、目录、访问统计和来源时间，才建立单独来源记录，并与取得的材料相连。普通保存不强制创建 Source 或 Job。

主动保存、选区、附注保留当时内容，自动更新不复用其可变对象或字节。自动内容的实用复用范围是“本机 profile、确切地址与获取方式”，称为本浏览器对该地址的当前观察，不声称是网站账户或永久业务身份。完整 query 和 SPA 路径参与地址，canonical 不决定覆盖。同一 profile 在同 URL 切换账户可能替换 current；需要保留的内容应主动保存。不建设账户识别或历史版本系统。

固定材料只在同一次本机请求恢复时尽力复用，两次主动保存可以形成两份有效资料。书签/历史按 profile 与原生 ID 尽力协调，重命名或移动不换身份；原生 ID 重置不承诺连续。来源记录与当前获取的时间分别保存，公开获取不能冒充历史现场。

自定义根合同使用 `extensions.web-collection.record.v1`、`extensions.web-collection.material.v1`；正文沿用 `core.html.v1`、`core.text.v1`、`core.pdf.v1`。领域包提供普通图读取和解释入口，另一 Peer 可沿普通关系读出标准语义叶子及出处，无需扩展运行。完整富文本 UI、新发行格式和所有 Peer 的预装解码器不在此阶段附带建设。

## 保存、恢复和残余

材料入本机持久待办后才确认“本机等待发送”。待办绑定原信息库和连接身份，切换当前连接不会重定向旧项；凭据缺失保留待办。使用现有连接绑定 DBAPIClient；PDF 只为现有字节传输补充精确连接与 token 的注入，不切换全局 SDK 配置。

后台串行分批工作，只要有实际尝试或持久化进展就继续，不靠 UI 轮询唤醒；同一轮已尝试的请求不立即重试，空闲后由新操作或 alarm 再次唤醒。按根和关系中可见的结果继续缺失部分；根存在不等于全部保存完成。所有本次材料及附注关系得到确认后才显示共享保存，并释放本机载荷。失败保留载荷和错误，不把部分完成显示为完整成功。

不承诺跨请求事务、全局 exactly-once、删除后永久防复活或跨语句同快照。响应丢失和跨实例竞争可能产生重复根、未关联语义块或孤立 blob；普通 LIVE 读可能遇到局部变化。恢复以已知对象及可见关联尽力复用，不建设操作日志、补偿或孤儿清理服务。业务能保持正常有用的结果，不能用“best-effort”隐藏错误或泄露秘密。

为查找普通 text 列中的领域根，候选用 UUID 或 scope/key 的派生十六进制查询键筛选，再核对完整身份；它不是唯一约束、来源 authority 或新注册系统。无实际规模压力前不新增索引字段或 JSON 查询 RPC。

本机队列有界，满时提示，不静默删除已接纳材料。同一未发出的自动观察允许合并为最新内容，已开始发送的请求不改载荷。手动工作先于导入与自动项，暂停的自动项不阻塞手动保存。暂停、排除和权限撤回停止尚未派发的自动工作；已派发效果不保证取消，也不为查清它继续上传。

HTML/text 不为事务而强制使用 binary Storage。PDF 使用显式选择的、此 Peer 有实现的可写 Storage；未选择时可用内置 PostgreSQL binary。若具体 Source 参与，仍遵守既有显式→部署默认→内置规则，本机普通保存不伪装成一个 Source。已配置但没有能力的存储明确报错，不偷偷 fallback。

## 浏览器取材与阅读

2026-10-23 接入修正：本地 Connection 表示本 WebExt 加入的信息库，不是向另一 Peer 上传材料的目的地。设置页直接读取同源完整配置；输入验证后即可本机保存，不强制重填密钥或等待联网。更新保留 connectionId/peerId，主人修正同库地址后待办继续使用该连接；另一个信息库使用新配置。登记和续租复用 core 的浏览器 Peer 运行时，在启动、配置保存及 alarm 中独立执行，失败可见但不阻断配置与 CRUD。UI 显示信息库及本 Peer 身份，PGRST301 只归类为该地址的认证失败，不推断为 Peer 拓扑或用户密钥类型错误。

自动默认关闭，按授权站点启用，非私密窗口、可见页面稳定后采集。保留无变化退避、隐藏停止及离开 best-effort 收尾；只对已入队材料承诺恢复。手动动作立即取得当前页、选区或可取的 PDF，不等待自动周期。

保留结构、文本、必要元数据和实际出处；排除未提交编辑/密码、脚本和扩展 UI，不读取 cookie 或网站 localStorage 猜账户。已加载 open Shadow DOM 和可读同源 frame 纳入；不可读 frame、虚拟化卸载内容和封闭组件明确列缺口。先用真实主体样本决定是否需要授权跨域聚合，不建设任意页面镜像。

公开网页获取不携带浏览账户凭据或 InKCre JWT，允许正常重定向，按响应与 HTML 声明解码。已知错误或登录页不报正文成功。在线 PDF 的显式保存可使用浏览器允许的会话，但不保证复现 viewer 网络状态；无法取得原始字节就明确保留链接或报失败。尺寸有界，不截断后报完整。

复用 Readability。Chrome 的 DOM 解析用随包 offscreen 页面，Firefox 使用可用 DOM 环境；不为保活而使用隐藏页面。保存内容不作为代码执行。首轮 reader 提供原文、出处、附注、HTML 源码和 PDF 下载，不要求完整富文本浏览器或 InfoBaseRouter 才算独立阅读。执行代码随扩展打包，不建设远程 Module Federation Host。

连接和大载荷留在合适的扩展持久存储，普通旧偏好不必全迁入新 KV。旧配置、待办按实际字段迁移，失败保留原值；不把旧 HTTP 服务地址猜成 PostgREST，不盲目重放未知旧请求。按用户追加决定，旧工具全部 hard-cutoff：删除 Explain/Writing Assist、选区浮栏、旧侧栏、模型设置及专用消息/依赖，只保留旧连接与摘录的数据迁移。设置页延续原有灰底卡片、白底字段、方角和 teal 主动作，使用紧凑 Switch，不另换视觉风格。

## 导入与执行 owner

一次浏览器导入由一个本机 runner 执行。预览书签目录或历史范围，确认后先保存来源事实，再取得当前内容；内容失败不丢收藏信息。保存范围、剩余项和必要阶段，关闭 popup 不取消，重开可继续。单项失败不停止整批，可以只重试失败项。

完成项用共享图的原生来源身份与关联尽力复用，不承诺并发重跑绝不重复。不保存另一套长期完成清单，不建设跨执行者世代/CAS/转移协议。停止剩余项，不删除已迁入资料，不伪造已发出请求的取消。展示记录、内容、已有项和失败/待补采等可行动状态，不把摘要或索引完成当保存前提。

第三方收藏服务待用户实际资料源明确后选择一个连接器，忠实迁入其正文、笔记、高亮和原时间，不降成 URL 转发。远端 Source/Job 的执行方式由该真实连接器决定；它不阻塞浏览器核心，也不提前建设一套分布式导入引擎。

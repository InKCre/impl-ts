# WebExt 版本、分发与深色标志

2026-10-25，用户接受小范围手动分发、未来商店复用发布流程的方案，授权连续完成技术、验收与实现。无 Chrome 开发者账号，不要求付费，不上传商店或正式发布。

## 实现边界

WebExt 继续作为独立 Peer。Changesets 为包记录 minor 意图，Release PR 生成版本和 changelog；新 WebExt workflow 只从当前受保护 main 发布已准备版本。一次构建生成 Chromium ZIP、Firefox 未签名 ZIP 和来源记录，GitHub Release 保存实际字节，未来签名及商店提交消费这些包。尚无签名时明确标注 Firefox 仅供临时加载，不把 ZIP 改后缀冒充已签名 XPI。发布失败可继续未公开草稿，已公开同版本不覆盖；不增加发布框架或自建更新服务。

Chromium 本地生成一次 RSA 身份，公钥进入 manifest，私钥仅在 owner 的仓库外配置目录保管，不进入源码或发布包。将来的商店身份承接没有当前后台证据，不能承诺；但无需重做版本、构建和发布归档。现有路径派生 ID 不是可逆的 RSA 身份，不覆盖日常安装。提供本机数据导出/导入，仅导入空实例，保留连接与 Peer ID、profile ID、完整待办/PDF、导入 checkpoint 和旧封存数据；跨 ID 不转移浏览器授权，重新授权后再继续。导出文件包含明文密钥，提示 owner 私下保管。临时过渡构建保留原路径身份，仅用于导出，不能作为固定身份的正式产物。

页面沿用现有 InkUI 和灰卡片风格，核对深浅主题 logo 实际选择。Firefox 使用原生 theme_icons 选择原色/反白 optical 16px 资产；Chromium 没有等价主题图标声明，使用 logo pack 自带白色画布的原色图标保证在深浅工具栏可辨识，不增加后台主题监听或 offscreen 文档。扩展管理图标同样选择有画布素材。所有素材直接复用原包，不重绘。

## 顺序与验收

1. 补固定身份、版本显示和主题图标，补同源本机数据转移入口；不触碰日常 profile。用真实隔离扩展验证空实例导入、已有数据拒绝覆盖、身份/队列/PDF/checkpoint 保留及深浅 logo。
2. 增加 Changeset、最小发布命令和 workflow，更新原有版本准备入口的名称。测试未准备版本跳过、版本/来源/浏览器产物匹配、公开版本不覆盖；本地构建 ZIP 并解压核对，不写 GitHub Release。
3. 验证固定公钥的不同目录身份一致，以及覆盖升级后已有连接、待办和导入进度可读；复用原有 Helium/sfp7 Firefox headless 旅程与 UI 截图，不下载或弹出浏览器。
4. 更新安装/升级/迁移说明、提交并更新 Draft PR。保留 Mozilla 签名、商店迁移、正式发布未验证边界，不将它们写成已完成。

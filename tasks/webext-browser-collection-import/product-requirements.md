# WebExt 浏览器采集与已有资料导入：产品需求提案

> 2026-10-22 用户接受[技术审计](technical-audit.md)并要求推进。已修订绝对去重/恢复及稳定引用表述：按实际损失保留有界恢复，不强制事务、永久回执或快照基础设施；产品能力范围不缩减。实现与证据见任务入口，原提案的阶段状态不代替最新授权。

2026-10-22，用户接受本版产品需求及完整重写方向，并授权继续收敛技术方案。新增明确约束：WebExt 本身是 Peer，不得对 client-web 产生硬依赖。本文件仍为任务内产品基线，尚未提升为共享权威文档，也不代表已经实现或验收。

## 产品目标与推荐范围

WebExt 让用户把浏览中的内容、过去积累的链接和收藏带进 InKCre。日常浏览时自动留存可用内容，需要明确表达意图时保存整页或摘录；迁入既有资料时同时保留原有收藏信息和能够取得的内容。采集结果进入共享 info-base，停止浏览器后仍可由其他具备读取能力的 Peer 使用。

完整重写 WebExt 的采集与导入业务流程，保留 WXT、Vue 和合用的共享能力。完整重写不等于另造基础设施。选区摘录纳入新采集旅程；用户随后明确要求旧工具全部 hard-cutoff，同时保留原 WebExt 的视觉风格，尤其是设置页的灰底卡片、白底字段与紧凑比例。

WebExt 必须独立完成连接、采集、导入控制及结果查看：不要求 client-web 已部署、页面已打开、共享其登录态或代理请求。两者可以共同依赖 SDK、数据库协议和内容合同；WebExt 可以按能力委托其他 Peer，但不能指定 client-web 为必经节点。打开 client-web 只可作为用户选择的便利入口。

| 能力                   | 推荐交付范围                               | 用户能够得到的结果                                                                      |
| ---------------------- | ------------------------------------------ | --------------------------------------------------------------------------------------- |
| 浏览中自动采集         | 首期核心                                   | 授权范围内的普通网页与常见 SPA，包括登录后已加载的内容；有暂停、页面/站点排除与状态反馈 |
| 主动保存               | 首期核心                                   | 保存当前页、选区及可选附注；保存可取得原始字节的在线 PDF                                |
| 浏览器历史和书签导入   | 首期核心                                   | 预览与筛选，保存来源信息并尝试批量取得当前内容；缺失内容可单独补采                      |
| 收藏/稍后读服务导入    | 完整目标内，首个连接器按用户实际资料源选择 | 在 WebExt 发起并查看导入；迁入服务提供的正文、笔记、高亮、标签和收藏信息                |
| URL 清单与在线 sitemap | 后续扩展                                   | 沿用按 URL 取得内容的旅程；不以链接递归遍历整个网站                                     |
| 本地文件与目录         | Mac Peer 的领域                            | 普通文件、磁盘目录和本地归档不在 WebExt 再做一遍                                        |

首期核心本身就是完整可用的一轮交付。第三方服务不因其执行位置而排除出产品目标，也不预先承诺一次接完七种服务。较小的首个体验切片可以先打通“手动保存 + 一批书签的内容导入”，但它不能替代自动采集和历史导入的最终范围。

## 日常浏览与主动保存

首次加入信息库时，用户能识别当前信息库及本 WebExt 的 Peer 身份，并选择是否开启自动采集。推荐在用户完成明确启用前保持关闭；开启后按授权站点工作，允许只采集指定站点，也允许排除页面或站点。历史、书签权限在进入对应导入入口时请求。首期不在私密窗口中自动采集。

自动采集使用可见标签页的已加载内容。这里的“可见”是标签页状态，不证明用户读过每段文字；页面下方尚未加载的内容、被虚拟列表移出 DOM 的内容也不能因此视为已保存。静态页面和登录后的动态页面使用同一条旅程，页面变化后继续补充当前内容。

保留 Hister 有价值的行为：页面稳定后采集，内容无变化时降低检查频率，SPA 导航后短暂等待，标签页隐藏时收尾并停止周期检查，恢复可见后继续。30 秒起退避到 5 分钟、约 1 秒导航安静窗口是上游已实现的参考值，不是 InKCre 在产品阶段必须冻结的性能承诺。用户点“立即保存”应立即开始保存，不等待自动周期。

已知 HTTP 错误页不自动存成正常内容。对于无法读取的页面、已识别的登录/验证码页面、缺少正文或主体不可访问的情况，给出原因或“仅取得部分内容”的反馈。不能以保存了网页外壳作为完整采集成功；也不承诺能够识别所有网站的缺失内容。

主动保存有三个相邻操作：“保存当前页”“保存选区”“添加附注”。摘录原文、用户附注与网页来源分别保留。保存选区不要求同时采集整页，适用于只愿意保存一小段内容的场景。它继承旧 Taking Note 的实际价值，不要求用户先手工编辑图关系。

在线 PDF 属于当前浏览器资料。能够取得原始 PDF 时保存原始内容和来源；只取得 URL 时明确显示“链接已保存，PDF 内容未取得”。本地 PDF 的打开与导入仍由 Mac Peer 承担。内嵌框架与开放 Shadow DOM 可能承载正文，应在技术阶段以实际阅读页面验证覆盖；不能仅按 DOM 技术名称宣布这些页面不在产品内。Canvas、视频或封闭组件没有可读取正文时，不声称已保存其内容。

## 保存结果、变化与控制

页面材料需要保留浏览器现场才能取得的渲染结构、文本和来源信息，后续应能重新进行内容解释。实际访问地址、页面声明的 canonical、观察时间和来源提供的时间分别记录。canonical 是来源提示；页面路径、查询参数和 SPA 路由也可能区分不同内容，不能只按 canonical 或粗略裁剪后的 URL 合并资料。

网页结构和文本应保留后续提取所需的语义。自动采集不读取 cookie 或网站本地存储，并排除密码、编辑框中未提交的输入和扩展自身界面；用户明确选择的摘录按主动采集意图处理。读取保存材料时不执行页面脚本。不能把所有结构化元数据一起删除，也不能因清理了表单就宣称登录页面没有私人内容。网页正文可能本来就是私人资料，采集范围由用户控制。

区分自动刷新与主动留存。自动采集尽力维护该浏览器对确切地址的当前观察，不承诺每次访问、每次变化都形成永久历史档案，也不证明网站账户身份。同一 profile 在同 URL 切换账户可能替换 current；重要内容需要主动保存。主动保存和摘录保留当时材料，后续自动刷新不能改写原文或附注。具体业务需要长期依据时保留必要原文与出处；普通来源引用不因此要求完整历史网页或读取前冻结。

这项默认的代价是：仅靠自动采集不能保证找回所有过去版本。若产品目标进一步包括网页改动取证或完整历史回放，应显式加入版本保留需求及其容量成本。

用户应能区分“已在本机等待发送”“已保存到信息库”“已排除”“需要处理”。断网或重启后，已入本机队列的材料保留并可继续；按已知对象和关联尽力复用，未知结果或并发重试仍可能留下重复、局部残缺或孤立项，不承诺全局 exactly-once。未完成不显示完整保存。待提交材料绑定采集时选定的信息库，切换连接不重定向旧材料。队列满时停止接受新自动材料并提示，不静默丢弃已接纳材料；同一未发自动观察可合并，手动不被暂停自动项阻塞。

暂停自动采集停止新的自动观察及尚未发送的自动项，手动保存仍可使用。排除规则生效后，匹配的未发送自动项也不得继续上传。已发出的请求可能已经成功，已存资料不由排除操作删除；界面把“以后不采集”和“处理已保存资料”分开。

原始材料已保存、后续提取待处理、检索尚未就绪是不同结果。保存成功以材料进入 info-base 为依据，不能等待摘要或语义索引成功才确认，也不能把本地排队显示成共享保存成功。

## 已有资料导入

用户在 WebExt 选择来源，查看范围与目标信息库，确认后迁入资料。浏览器历史按最近访问日期、站点及可用的访问次数筛选；书签按目录筛选。首期只读取当前安装扩展的浏览器资料，不假设能直接访问其他浏览器的磁盘数据库。

推荐默认选择“导入记录并取得当前内容”，同时提供“只导入记录”。这既保留原收藏信息，也把可用正文实际带进 info-base，而不要求用户重访每个链接。预览明确告知将访问哪些网站、预计条目量；导入以受控速度运行，可以停止尚未执行的工作。

| 取得的材料                     | 导入行为                                     | 必须保留的区别                                         |
| ------------------------------ | -------------------------------------------- | ------------------------------------------------------ |
| 浏览器历史/书签提供 URL 与标题 | 保留来源信息，并按用户选择请求当前内容       | 过去访问/收藏时间与当前获取时间不同                    |
| 服务已经保存正文或文章快照     | 优先迁入服务实际提供的内容                   | 服务保存的版本与今天原网站的版本不同                   |
| 服务提供笔记、高亮、标签或目录 | 与相应资料一起迁入                           | 用户附注、高亮原文和来源正文不能混成无法分辨的一段文字 |
| 只有链接，没有可用正文         | 尝试获取当前页面                             | 获取失败不影响已经保存的收藏与笔记                     |
| 页面需要登录、交互或验证码     | 保留记录并标为需要现场补采，用户可打开后保存 | 不继承过去登录态，也不自动批量打开用户的登录页面       |

第三方服务的一次性导入可以由适合的 Peer 执行，WebExt 继续提供配置、预览、启动和结果入口。Linkding、Linkwarden、Karakeep、Raindrop、Readeck、Shaarli、Wallabag 都是候选；先接哪一个取决于用户的真实资料库。连接器必须忠实处理其实际提供的材料，不能只做一个所有服务通用的 URL 转发器。没有网页 URL 的笔记，只要已选服务能提供，也不能沿用 Hister 的单 URL 文档约束直接丢弃。

进度分别显示记录已导入、内容已取得、仅有记录、待现场补采、失败和按规则跳过。浏览器重启、执行 Peer 暂时离线后仍可恢复或明确显示等待条件；关闭 popup 不等于取消。单条失败不终止整批，用户可只重试失败或缺内容的条目。取消停止剩余工作，已迁入资料保留。

重复导入按已知原生身份和可见关联尽力复用完成项，不承诺并发绝不重复；已有笔记不被新抓正文覆盖。同一个 URL 的书签、访问和服务收藏可以保持关联，但它们不因地址相同就互相替代。不承诺完整逐次访问时间线。删除原书签或清空浏览器历史不自动删除 info-base 中的内容；首期为主动导入与按需重跑，不默认建设双向或持续同步。

## 与现有能力的协作

| 所有者                            | 本提案需要的职责                                                                             |
| --------------------------------- | -------------------------------------------------------------------------------------------- |
| WebExt                            | 浏览器现场材料、选区与出处、浏览器历史/书签访问、交互与待提交恢复；统一发起导入              |
| Collection / 各 Source            | 忠实接纳来源内容、保留来源身份与时间、恢复导入；可以按已确认合同构造 Blocks 与 Relations     |
| Storage / Resolver / 内容提取能力 | 读取实际字节、安全呈现、忠实解释内容；正文提取的具体归属由其现有合同和并行研究决定           |
| Organization                      | 基于已有材料进行归纳、关联等改善后续使用的工作；不成为“保存原材料”的强制前置条件             |
| info-base query / sinks           | 检索和对外使用；WebExt 不再维护另一套搜索索引或问答实现                                      |
| Capture                           | 已有主动文本/图片材料与附注合同是选区保存的复用候选；整页、在线 PDF 与浏览器导入需要另行定义 |
| Mac Peer                          | 本地文件与系统采集；不要求它充当 WebExt 访问共享信息库的必经节点                             |

共享契约允许 Collection 构图，忠实文本解释也不等于 Organization。产品边界不应写成“WebExt 绝不拆 Block”或“所有正文提取都是 Organization”。这里的要求是采集与来源表达遵守统一合同，后续处理可以重用材料，不在 WebExt 固化一套独立知识组织体系。

当前 Capture 合同明确排除整页抓取。本次网页材料身份、保存/刷新、重试及本机完成状态采用[修订技术方案](technical-design.md)和 TS owner 的 WebExt TDD，使用普通图协议，不预设 Python 业务 RPC，也不扩大现有 Capture 请求。后续真实服务连接器再按能力选择 Job 或精确 Peer 委托。

## 旧扩展的重写与迁移

现有证据来自 `apps/client-webext/entrypoints/background.ts`、`entrypoints/content/ContentScripts.vue`、`entrypoints/taking-note.sidepanel/TakingNote.vue`、`logic/task.ts` 和 `wxt.config.ts`。background 主要处理 side panel 和 tab ID；页面内容路径按消息调用 Readability 后只返回 textContent；选区笔记通过旧表单写图。当前未发现页面自动观察、历史/书签导入、对应恢复流程或专属测试。

这些缺口支持重写采集与导入的核心流程，尚不能证明 WXT、Vue、配置适配器或每个组件都没有复用价值。当前仅有源码与文档证据，未运行旧扩展的真实浏览器旅程，不能据此把所有旧功能称为不可用。

迁移保留“选文字、附注、保存出处”的价值，以已确认的新合同替换旧写入路径。按用户追加指令，Explain、Writing Assist、旧浮栏和侧栏、模型设置全部删除，没有兼容开关或旧运行入口。已有连接与未完成摘录保留只读迁移，不随功能删除清空数据；已经保存的信息不受影响。

浏览器交付建议先以 Chromium 打通完整旅程，再验证 Firefox 的同一产品合同；当前 README 声称支持两者，不能只凭构建命令宣布行为兼容，也不在本轮默默撤销 Firefox 目标。

## 如何判断交付完成

| 场景                                  | 应看到的结果                                                                               |
| ------------------------------------- | ------------------------------------------------------------------------------------------ |
| 授权范围内浏览普通网页和登录态 SPA    | 不用逐页点击即可留存已加载材料；未加载和无法取得的内容不被宣称已保存                       |
| 页面无变化、隐藏、恢复、SPA 导航      | 不持续重复写入或隐藏轮询；在普通离开流程中交接最后变化，不保证浏览器崩溃前未入队的瞬间内容 |
| 暂停或排除当前站点                    | 后续自动采集和未发送自动项停止；明确手动操作仍可保存一次                                   |
| 手动保存选区并加附注                  | 原文、附注、来源可区分，网页随后变化不改写摘录                                             |
| 保存在线 PDF                          | 原始内容可从 info-base 读取；无法取得字节时明确只保存了链接                                |
| 离线保存后重启，再恢复网络            | 已入队材料仍在，目标不变，复用已知结果继续；未知结果重试可能有重复，不误报完成             |
| 一批书签/历史含普通页、失效页和登录页 | 正文可用项实际带入内容；失败项保留来源并可重试或现场补采；时间语义正确                     |
| 重跑同一导入并取消剩余任务            | 尽力复用已知完成项，未完成项可继续，取消不删除已完成材料                                   |
| 已选服务有文章快照、笔记或高亮        | 其实际提供的材料与出处被保留，当前网页抓取不会覆盖服务保存版本或用户笔记                   |
| 浏览器停止、后续组织或索引尚未执行    | 已保存材料可由另一个具备读取能力的 Peer 解释；状态不伪称提取或索引已完成                   |

验收使用真实浏览器/数据库上的可控页面与原生资料夹具，并补代表性公开页面；断网、重启、重复导入和局部失败检查恢复边界。本表是产品判据，最新运行结果与未覆盖范围记录在实施接续，不把构建或合成资料当成真实私人资料库全覆盖。

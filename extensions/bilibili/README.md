# B 站收藏夹

`inkcre/bilibili` 的 Module Federation Distribution，为 Web Peer 提供自己的 B 站收藏夹采集与读取能力。采集通过用户明确选择的浏览器执行，沿用其中的 B 站登录态；资料保存到共享信息库后，其他加载此插件的 Web Peer 可以独立读取。

## 使用

1. 在 InKCre 浏览器扩展设置中授权当前 Web 地址，并在同一浏览器登录 B 站。
2. 打开插件设置，查找并选择该浏览器，读取 B 站收藏夹。
3. 确认显示的账号，选择一个或多个自己的收藏夹并保存采集源。
4. 开始采集。任务使用普通 Source / Job 路径，由具备此 Source 实现和对应浏览器绑定的 Web Peer 领取。
5. 查看采集状态和已保存资料。单次分页预算用完时，任务可以正常结束，但设置会明确显示仍有未完成范围；再次执行会校验边界后继续。

MF Distribution 提供采集与独立读取能力。Python 的只读 Distribution 解释相同 v1 图合同，供既有读取与词法检索使用；它不是采集控制者，采集不要求运行 Python 业务进程。设置、账号确认或查找浏览器不会自动创建采集任务。运行期间应保持 Web Peer 与所选浏览器在线。任务运行时可以请求取消，界面会等待实际终态，不将请求发出等同于已经停止。

## 保存范围

- 自己创建且明确选择的收藏夹，包括私密收藏夹。
- 收藏夹、视频、UP 主的原生身份和实际取得的标题、简介、链接等资料。
- 收藏关系，以及来源明确返回的收藏时间、位置和条目可用性。同一视频位于多个收藏夹时共用视频实体。
- 多 P 视频仍以被收藏的视频对象为单位。

本版不保存视频二进制，不下载字幕或评论，也不修改 B 站收藏。封面仅保存来源 URL；来源图片失效不会影响已保存的文字与关系。私密收藏夹的资料同样进入当前信息库，请按自己的信息库访问范围选择。

## 完整性与重复执行

分页以来源的 `has_more` 为准，短页不能被当成末尾。恢复前复核列表首批、数量和已提交分页边界；观察到变化时重新扫描。末批提交前再次核对首批和报告数量，发现变化则保留已确认批次并明确失败，供下一次重新核对。页码只是可复核的执行提示，不是永久信息身份。

“分页已遍历”仅表示可见分页到达结束标记并通过上述边界检查。界面同时显示累计返回条目、来源报告数量和差额；来源可能隐藏部分条目或异步更新计数，差额不能被当作已成功取得。列表在采集期间变化时，本版不承诺某一时刻的原子快照，也不声称能检测任意中间位置的重排。

每批图变化和进度通过数据库 `commit_source_batch` 同事务确认。未知写入结果不会自动重放。再次采集复用原生身份和既有 Block，保留用户添加的关系；本版不会根据未出现的条目删除历史收藏资料。

失效占位标题不会覆盖已有标题或简介。非视频和身份不足条目计入未支持或未解析数量。未登录、账号变化、挑战响应、分页异常或断连会使任务明确失败，不能被当成空收藏夹成功。

## 开发与验证

```sh
pnpm --filter @inkcre/ext-bilibili test
pnpm --filter @inkcre/ext-bilibili type-check
pnpm --filter @inkcre/ext-bilibili build
```

单元回归使用虚构身份和文本，只复用实际观察到的响应字段形状；不在仓库保存用户私人收藏响应。真实浏览器链和私密收藏夹验收由主任务记录单独报告。

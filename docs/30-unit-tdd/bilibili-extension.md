# B 站收藏夹插件

本文适用于 `inkcre/bilibili` Web MF Distribution 的维护者。共同产品承诺与跨 Distribution 合同由共享文档拥有；本 Unit 负责浏览器站点适配、Source 执行、图投影及读取界面。Python 只读 Distribution 解释相同 v1 记录，为既有读取和词法检索提供能力，不拥有或控制 Web Source 的执行。

## 所有权

插件拥有 B 站账号、收藏夹、视频和收藏条目的解释，站点路径与接口字段也留在插件内。通用 Core / Web-ext 只提供浏览器绑定、Puppeteer Page、消息桥和会话生命周期，不包含 B 站选择器或业务模型。Web Peer 以普通 `core.source.collect.v1` Job 执行 Source。

首版范围为用户自己创建且明确选定的收藏夹，含本人可访问的私密收藏夹。账号、收藏夹选择和浏览器绑定写入 Source 配置；浏览器 cookie、密码和视频二进制不会写入配置或业务图。第三方站点接口不是 InKCre 对外稳定合同，其响应由 `site.ts` / `normalize.ts` 转换。

## 共享图的本地实现

四个精确 Resolver 为 `extensions.bilibili.user.v1`、`folder.v1`、`video.v1`、`membership.v1`，完整前缀相同。领域内容校验由 `schema.ts` 执行。账号以 MID、收藏夹以完整 media_id、视频以 aid 标识；BVID 是已知视频别名，原始 fid 不能代替 media_id。

账号到收藏夹使用 `owns`，收藏夹到成员使用 `contains`，成员到视频使用 `item`，视频到 UP 主使用 `author`。成员自己的 Block 承载可变收藏时间、观察位置与条目可用性；稳定边不把这些值串入身份。观察位置明确为 `page_number` 与 `position_in_page`，不由分页大小推算并声称原生绝对顺序。内容不重复保存跨实体关联作为第二份权威。

扩展通过普通 Block / Relation API 自行核对原生对象，每次执行读取已有 B 站内联 JSON 块，以实际解析出的 MID、完整 media_id 或 aid 复用 Block。查询按 Resolver 和普通分页限定范围，JSON 空格与属性顺序不参与身份判断。成员身份来自明确的收藏夹 `contains` 成员 `item` 视频路径；v1 成员内容不增加 folder_id、aid 或私有 native_key。执行中的内存查找表不作为共享权威，也不保存第二份持久身份账本。

来源没有取得的字段不写入 patch，扩展在已有 JSON 对象上合并已知字段。失效视频的占位标题、空缺作者或简介不能抹掉已保存事实。独立视频身份不依赖某次 Source 或浏览器，重复采集和跨收藏夹采集复用相同 Block；本次采集只补齐自己的稳定边，不删除用户关系。

## 批次与恢复

`collect.ts` 按配置的收藏夹逐一读取，每批最多处理一个 20 项分页；`has_more` 是结束依据。来源可能返回不足 20 项但仍有后续，不能用条目数代替结束标记。

Source.state 仅保存范围、分页提示、首批和已提交边界的身份序列、进度及计数，不存平行信息内容。继续前比较首批身份、来源报告数量及已提交边界；不同则从头重新核对该收藏夹。此策略减少普通新增和移动造成的漏取，不提供实时列表的原子快照或自动删除语义。

末批提交前重新读取首批，对照本轮首批身份、起始报告数量与末批报告数量；发生变化时不提交“完成”，保留此前已确认的批次，并使 Job 明确失败。完整遍历与条目全数取得是不同声明：每个收藏夹同时保留累计返回、解析视频、失效、未支持、未解析数量和来源报告数，设置界面展示差额。数量不等本身不会触发无限重扫，也不能被隐去后声称完整；此边界检查不检测任意中间位置变化。

每页先确认对象和关系写入，最后以普通 Source 更新保存进度。失败停止，创建结果未知时不在同一次执行中重放。下一次执行重新读取普通图：已可确认身份的对象和完整成员路径会被复用，缺失的边会被补齐；在成员身份路径尚未形成前中断可能留下孤立块，不为消除此残留增加持久账本。本版不保证并发首次创建唯一或整页原子可见。

`Source.block` 指向该 Source 独占的 `core.source.v1` 锚点，锚点以稳定 `collects` 边指向共享账号业务根。没有锚点引用时先按普通图中的 Source id 查找，避免因一次来源锚点创建响应丢失就直接重复创建；锚点和业务账号不能互换。最后更新 Source 的锚点引用与进度。不同 Source 可采集同一个账号而保持各自来源身份。设置变更只更新配置，不顺便写业务图。

## 读取

Resolver 仅依赖已保存的 Block 和稳定关系；不会为读取而连接原浏览器或调用 B 站。收藏条目按归档关系分批读取，每次最多 50 个并提供继续入口，避免大收藏夹在单个图预览中被截断。视频所在收藏夹经成员 Block 反向解析，收藏时间与可用性跟随对应成员显示。

首轮仅保存元数据。原文和封面 URL 仍指向来源；文字和关系的离线使用不取决于这些链接继续可用。视频播放、字幕、源站编辑与失效内容恢复不在此 Unit 的当前承诺中。
